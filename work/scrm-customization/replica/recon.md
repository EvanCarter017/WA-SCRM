## Flows

B01 接入与首响
    Facebook来源 → WhatsApp接入 → 匹配/创建客户 → 分配负责人 → 回复或生成待办
    happy path clicks: 未测；属于拟建业务流，不编造点击数
    edge: 来源未知仍可接待；重复消息不重复建档；无人可接时进入队列

B02 线索到成交
    客户需求记录 → 可配置销售阶段 → 跟进任务 → 报价/外部订单 → 状态同步
    happy path clicks: 未测；属于拟建业务流，不编造点击数
    edge: 拒绝、无回复、客户转交、取消与退款要有路径；点击数不等于成交数

B03 售后与复购
    已完成订单 → 售后/问题处理 → 合适时机的联系任务 → 新订单或停止联系
    happy path clicks: 未测；属于拟建业务流，不编造点击数
    edge: 客户退订、投诉或问题未解决时停止相应自动化

B04 归因与复盘
    来源记录 + 会话 + 阶段变更 + 订单事实 → 内部经营报表 → 按授权决定外部回传
    happy path clicks: 未测；属于拟建业务流，不编造点击数
    edge: 无法匹配的来源、退款和重复事件独立处理；保留审计

B05 团队扩展
    创建组织/团队 → 邀请成员 → 分配角色和资源范围 → 配置队列/规则 → 审计
    happy path clicks: 未测；属于拟建业务流，不编造点击数
    edge: 人数和账号增加只调整资源/配额，不复制业务代码

## Inferred data model

客户与身份: Customer、ContactIdentity
    relationship: 一个客户可关联多个渠道身份；合并须可追踪
    confidence: 建议模型，非原站数据库事实

沟通: ChannelAccount、Conversation、Message
    relationship: 消息保留来源账号、方向、投递状态、原文和译文
    confidence: 建议模型，非原站数据库事实

销售: Lead、PipelineStage、Activity、Task
    relationship: 线索与客户分开；每个待办有负责人、到期和结果
    confidence: 建议模型，非原站数据库事实

交易关联: QuoteRef、OrderRef、FulfillmentRef
    relationship: 保存外部业务对象引用与摘要，不把供应商充值当客户订单
    confidence: 建议模型，非原站数据库事实

运营事件: SourceTouch、BusinessEvent、AttributionLink
    relationship: 来源证据与归因结果分开，保存规则版本与置信度
    confidence: 建议模型，非原站数据库事实

治理: Workspace、Team、Membership、Consent、AuditEvent
    relationship: 权限按组织和资源范围控制，行为和自动化可追踪
    confidence: 建议模型，非原站数据库事实
