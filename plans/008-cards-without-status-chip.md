## Why this matters

Plan 007 added a row of customer tags to the customer cards in the chat list of the WhatsApp API page (`#inbox`). After seeing it, the product owner said on 2026-11-17:

> "Why are there still no tags appearing on the customer card? Instead of showing the funnel stage, it should display the tags that were created in the tag management section."

What the owner saw: the cards carry a small chip on the right of the account line with the follow-up status (`客户待回复`, `跟进已逾期`, `跟进断档`, `复联待处理`, `已结束跟进`). It reads like a stage, and it is not one of the tags from tag management. (No tags were visible because a tag appears on a card only after it has been attached to that customer, and the prototype starts without tags.)

After this plan the cards no longer carry that chip. The only status-like labels on a card are the customer's own tags (the row plan 007 added) and the tier badge. The follow-up status stays everywhere else it is shown today: in the strip above an open conversation, in the follow-up centre and on the dashboard.

### Decisions already made (do not re-open; do not ask)

1. "The funnel stage" on the card is the follow-up status chip (`<span class="mini-stage">`). It is the only stage-like label on the card.
2. The chip is removed, not restyled or moved. Nothing replaces it; the tag row from plan 007 stays exactly as it is, below the account line.
3. The follow-up status itself (the `lcHealth` function, the strip above the conversation, the follow-up centre, the dashboard signals) is untouched.
4. The prototype still starts without any tags, and tags are still attached to a customer by hand. No demo tags are seeded and nothing is assigned automatically.
5. The baseline style rule for `.mini-stage` lives in the frozen baseline and stays there unused.
6. The version string stays `0.8-scrm-engagement`.

### Step 1: Create the browser smoke script (outside the repo) and record the baseline

Save this script at the fixed path `/tmp/wa-scrm-plan-008/smoke.sh` (outside the repository; always call it by this literal path, from inside the repository). If your shell rejects heredocs, write the same content with your file-writing tool and then `chmod +x` it.

```bash
mkdir -p /tmp/wa-scrm-plan-008 && cat > /tmp/wa-scrm-plan-008/smoke.sh <<'EOF'
#!/usr/bin/env bash
# Renders each view of the standalone bundle in headless Chrome and checks it.
set -u
ROOT=$(git rev-parse --show-toplevel); OUT=$(mktemp -d); FAIL=0
HTML="$ROOT/outputs/whatsapp-scrm-lifecycle.html"
strip() { node -e "const fs=require('fs');const s=fs.readFileSync(process.argv[1],'utf8').replace(/<script[\s\S]*?<\/script>/g,'').replace(/<style[\s\S]*?<\/style>/g,'').replace(/<!--[\s\S]*?-->/g,'');fs.writeFileSync(process.argv[2],s)" "$1" "$2"; }
for view in dashboard inbox accounts customers followups chat-records tags tag-stats materials ai scope; do
  prof=$(mktemp -d)
  timeout 90 /usr/bin/google-chrome --headless=new --no-sandbox --disable-gpu --user-data-dir="$prof" --enable-logging=stderr --v=0 --virtual-time-budget=4000 --dump-dom "file://$HTML#$view" 2>"$OUT/$view.log" >"$OUT/$view.html"
  rm -rf "$prof"
  strip "$OUT/$view.html" "$OUT/$view.txt"
  errs=$(grep -ciE 'Uncaught|ReferenceError|TypeError|SyntaxError' "$OUT/$view.log")
  size=$(wc -c <"$OUT/$view.txt")
  echo "view=$view js_errors=$errs rendered_bytes=$size"
  { [ "$errs" = 0 ] && [ "$size" -gt 15000 ]; } || FAIL=1
done
need() { grep -q "$2" "$OUT/$1.txt" && echo "ok   $1 contains: $2" || { echo "MISS $1 should contain: $2"; FAIL=1; }; }
gone() { grep -q "$2" "$OUT/$1.txt" && { echo "LEFT $1 should not contain: $2"; FAIL=1; } || echo "ok   $1 does not contain: $2"; }
inbundle() { grep -qF "$1" "$HTML" && echo "ok   bundle contains: $1" || { echo "MISS bundle should contain: $1"; FAIL=1; }; }
notinbundle() { grep -qF "$1" "$HTML" && { echo "LEFT bundle should not contain: $1"; FAIL=1; } || echo "ok   bundle does not contain: $1"; }
need inbox 'data-action="openConversation"'
need inbox 'conversation-account'
gone inbox 'mini-stage'
gone inbox '跟进已逾期'
gone inbox 'conversation-tags'
need dashboard '跟进已逾期'
need chat-records '归档会话'
need ai '能力清单'
inbundle 'function lcConversationTags(c)'
notinbundle 'title="跟进状态：'
echo "artifacts: $OUT"
[ "$FAIL" = 0 ] && echo "SMOKE PASS" || { echo "SMOKE FAIL"; exit 1; }
EOF
chmod +x /tmp/wa-scrm-plan-008/smoke.sh && ls -l /tmp/wa-scrm-plan-008/smoke.sh
```
