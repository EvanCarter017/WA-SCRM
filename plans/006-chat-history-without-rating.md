## Why this matters

Plan 004 turned the chat-history page (`#chat-records`, "聊天记录") into an archive of conversation snapshots that are moved in from the WhatsApp chat. On the advisor's own initiative it also added a review panel on the right (a result — 待质检 / 合格 / 需改进 — plus a comment), a filter by that result, and result labels in the list. After seeing it, the product owner said on 2026-11-17:

> "The chat records do not need that rating system on the right, nor do they need to be categorized as 'qualified' or 'unqualified.'"

This plan removes the rating panel, the filter by result, the result labels and the related wording. Everything else stays: moving a conversation in from the chat (with a reason), the list of archived conversations, the read-only snapshot with message search and the translation switch, the snapshot facts on the right, opening the live chat, and removing a snapshot.

### Decisions already made (do not re-open; do not ask)

1. The **whole** review form goes — the result selector, the comment box and the save button — not only the result selector.
2. The filter by result, the "pending review" count, the result label in the list and the result pill in the snapshot heading go too. With no filter left, the filter form becomes a plain toolbar holding the "从 WhatsApp 会话移入" button and the archive count; its "筛选" and "重置" buttons go.
3. The wording "质检" (quality inspection) implies pass/fail and is replaced: the purpose is described as "绩效复盘与审核" (performance review and auditing — the owner's own words), and the module is called "聊天记录归档".
4. A conversation whose current content is already archived cannot be moved in again (same customer, same number of messages). Before, this was refused only while the earlier snapshot was still unreviewed.
5. Snapshots saved in a browser by the previous build may still carry a `review` field. It is simply no longer read; no migration code is added.
6. The version string stays `0.8-scrm-engagement`.

### How requirement notes saved in a browser are restored

The app keeps a visitor's requirement decisions and notes in `localStorage` and restores them over the built-in ones. A map named `previousDefaultNotes` (inside the second argument of one `swap` near the top of `build-fidelity.cjs`) lists earlier **default** notes of modules whose scope was revised, so that a stale default note is replaced by the new one while a note the visitor typed is kept:

```js
      const previousDefaultNotes={'P-AUTO':'不因原产品存在而自动纳入。','P-TEAM':'角色切换仅用于原型评审，不是生产鉴权。'};
      const revisedScope=Object.hasOwn(previousDefaultNotes,module.id)&&previous.basis!==module.basis;
```

The default note of `P-CHAT-REVIEW` written by plan 004 mentions the rating, so Step 5 adds it to this map.
