## Why this matters

The owner decided on 2026-11-21 to turn the prototype into a product ("Transition everything from a prototype state to a production-ready state"). Since plan 023 the page signs in, keeps its data on the server and starts empty. Three kinds of prototype leftovers remain in the repository and do nothing any more, or no longer work:

1. **Code that added sample content** on first use: sample customers with their follow-up records, sample orders and their shipping history, two sample archive entries, a clean-up of preset tags that needs the fictional data set, and one sample material. Plan 023 switched it off for new sub-sites with marks in their first document; this plan deletes the code and the marks.
2. **The two single-file bundles** `outputs/whatsapp-scrm-lifecycle.html` and `outputs/whatsapp-replica-ui-fidelity.html`: opened as files they can only say that the server cannot be reached.
3. **The Windows launcher** `启动SCRM原型预览.cmd`: it starts the server without a data folder, where nobody can sign in.

### Decisions already made (do not re-open; do not ask)

- `lcSeed()` in `fidelity-lifecycle.js` keeps its name and its last part — the loop that gives every customer an engagement state and safe defaults. Only the three blocks above that loop go.
- `fidMigrateTags()` in `fidelity-ui.js` stays; only its call of the removed function goes.
- The baseline folder `work/wa-replica/fidelity-base/` is not touched (its `demo-data.js` stays there unused).
- The simulated WhatsApp actions (scan, incoming message, new lead, the sample chat after a simulated scan) stay; the real connection replaces them later.
- `重新构建原型.cmd` (it only runs the build) stays.
- Data of existing sub-sites keeps its old marks; they are harmless and are not cleaned up.
- The version string and `requirement.updatedOn` do not change.

## Current state

### What this repository is

A zero-dependency web app for an internal WhatsApp customer workbench: plain HTML/CSS/JS in the browser and a small Node server (`work/wa-replica/serve.cjs`) with accounts and one sub-site's data (Node 22.13 or newer). There is no package.json. Documentation text is **Simplified Chinese**.

### How the build works

`work/wa-replica/build-fidelity.cjs` reads a frozen baseline app, applies string substitutions, puts the module files (`fidelity-*.js`) into the same function and writes `outputs/wa-replica-prototype/*`. It also still writes the two single-file bundles, with these lines near its end:


**Never change an existing `swap` call. Outputs are committed and must be regenerated by running the build, never edited by hand.** Restore the icon pool from git before every build (command below).
