## Why this matters

In the `订单追踪` tab of the customer profile drawer the head of every order block carries text buttons: the advance button (`标记已发货` or `标记已签收`), `标记异常`, `撤销上一步`, and an icon-only remove button. Which buttons exist depends on the order's status, and their labels differ in width, so the group changes size from one status to the next: with two text buttons it sits on the heading line at the right, with three it no longer fits and drops to a second line at the left, and the remaining buttons move whenever one appears or disappears. The product owner reviewed it on 2026-11-18 and said:

> "When the status is "Pending Shipment," the button's position shifts, which can be visually distracting; could we replace it with a logo plus a tooltip instead?"

After this plan every action in the head of an order block is an icon button with a tooltip, and each icon keeps its place whatever the order's status is.

### Decisions already made (do not re-open; do not ask)

1. All actions in the head of an order block are icon-only buttons (the existing class `icon-button`), in this order: advance, exception, undo, remove. Each has a `title` (the tooltip) and keeps its `aria-label`.
2. Tooltips: the advance icon `标记已发货` or `标记已签收` (the next step), the exception icon `标记异常`, the undo icon `撤销上一步`, the remove icon `删除订单`.
3. Icons, all already in `icons.js`: the advance icon is the icon of the status it leads to (`Send` for shipped, `CircleCheck` for delivered — taken from `LC_SHIPPING` as today), `TriangleAlert` for exception, `RotateCcw` for undo, `Trash2` for remove. The advance icon is drawn in the accent colour and the exception icon in the danger colour, both existing colour tokens.
4. Positions stay fixed. The undo icon is **always** rendered; when the order has only its first entry it is disabled (greyed out) with the tooltip `暂无可撤销的步骤`, instead of being left out as plan 013 had it. The advance and exception icons are left out for delivered orders and orders in exception, as before; the group is aligned to the right, so the undo and remove icons do not move when they disappear.
5. Behaviour does not change: the same actions (`lcOrderShipping`, `lcOrderUndo`, `lcOrderRemove`) with the same data attributes. A disabled undo button does nothing, and `lcOrderUndo` already refuses an order with one entry.
6. One block of CSS is added for the two icon colours and the disabled look. No new icon, no new colour value.
7. The version string stays `0.8-scrm-engagement`.

```js
        return `<div class="lc-card-block lc-order">
          <div class="lc-block-head lc-order-head">
            <h3>${icon('ClipboardList')}订单 ${esc(o.number)}<span class="lc-order-time">下单时间 ${esc(fidDate(o.placedAt))}</span></h3>

              ${history.length > 1 ? fidButton('撤销上一步', 'lcOrderUndo', 'RotateCcw', 'slim', `${stepAttrs} aria-label="订单 ${esc(o.number)}：撤销上一步"`) : ''}
```

## Maintenance notes

- The head of an order block has four icon slots: advance, exception, undo, remove. The group is right-aligned, the undo and remove icons are always rendered, and the two step icons are rendered together or not at all — that is what keeps every icon in place. A new action should be added as a further always-rendered icon, or to the left of the step icons.
- Tooltips are native `title` attributes, as elsewhere in the prototype; the `aria-label` carries the order number for assistive technology.
- A disabled undo icon cannot be clicked, and `lcOrderUndo` refuses an order with a single entry on its own, so the two guards do not depend on each other.
- What a reviewer should scrutinise: no text is left inside the four buttons; the data attributes of each button are unchanged (`data-id`, `data-customer`, `data-shipping`); the icons do not move between statuses; `icons.js` is byte-identical.
- `validation.json`: re-run the validator once in the main checkout after merging from a worktree.
