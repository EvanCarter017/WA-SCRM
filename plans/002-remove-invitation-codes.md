## Why this matters

The product owner instructed on 2026-11-17: *"Remove all content related to invitation codes."* Invitation codes (`邀请码`) are a concept inherited from the third-party product this prototype was modelled on. The prototype has no invitation-code data at all — the values shown are synthetic (`WA-001`, `WA-002`, … derived from an account's position in a list) — yet the term appears as a table column, a search field and three filter controls. After this plan, no page, dialog, filter, table, data field or built file of the working prototype mentions or uses invitation codes.

### Scope decision already made (do not re-open)

"All content" means the **working prototype**: its module sources, its styles, its built outputs and its validator. It does **not** mean the historical and reference records, which this repository deliberately preserves unchanged and which describe the original third-party product or past snapshots:

- `work/wa-replica/archive-v05-fidelity.html` (the v0.5 snapshot backup named in `DESIGN.md`)

- `replica/fidelity/reference-geometry.json` (measurements of the original site)
- `plans/001-engagement-loop-without-lifecycle.md` (a finished plan that quotes old code)

## Current state

### What this repository is

A zero-dependency, offline, clickable **prototype** of an internal WhatsApp customer workbench: plain HTML/CSS/JS, no framework, no package.json. UI text is Simplified Chinese.

### How the build works

`work/wa-replica/build-fidelity.cjs` reads a frozen baseline app (`work/wa-replica/fidelity-base/app.js`), applies string substitutions, and concatenates the module files into the body of one IIFE in this order: `fidelity-ui.js`, `fidelity-customer-pages.js`, `fidelity-operations.js`, `fidelity-openwa.js`, `fidelity-dashboard.js`, `fidelity-lifecycle.js`, `fidelity-subsite.js`. All files share one scope, so a helper defined in `fidelity-ui.js` is callable from the later files. It writes `outputs/wa-replica-prototype/*` and two identical standalone bundles, `outputs/whatsapp-scrm-lifecycle.html` and `outputs/whatsapp-replica-ui-fidelity.html`. **These outputs are committed and must be regenerated by running the build, never edited by hand.** CSS is built from `fidelity-base/app.css` + `fidelity.css` + `fidelity-dashboard.css` + `fidelity-lifecycle.css`.

Icons: the build takes icon definitions from the existing `outputs/wa-replica-prototype/icons.js` and writes back only the icons still referenced. Restore that file from git before every build (command below) so the icon pool is always the same.

### Step 1: Create the browser smoke script (outside the repo) and record the baseline

Save this script at the fixed path `/tmp/wa-scrm-plan-002/smoke.sh` (outside the repository; always call it by this literal path, from inside the repository). It renders every page of the standalone bundle in headless Chrome (`/usr/bin/google-chrome`), fails on any JavaScript error, and checks that the term is absent from the rendered page.

```bash
mkdir -p /tmp/wa-scrm-plan-002 && cat > /tmp/wa-scrm-plan-002/smoke.sh <<'EOF'
#!/usr/bin/env bash
# Renders each view of the standalone bundle in headless Chrome and checks it.
set -u
ROOT=$(git rev-parse --show-toplevel); OUT=$(mktemp -d); FAIL=0
HTML="$ROOT/outputs/whatsapp-scrm-lifecycle.html"
strip() { node -e "const fs=require('fs');const s=fs.readFileSync(process.argv[1],'utf8').replace(/<script[\s\S]*?<\/script>/g,'').replace(/<style[\s\S]*?<\/style>/g,'').replace(/<!--[\s\S]*?-->/g,'');fs.writeFileSync(process.argv[2],s)" "$1" "$2"; }
for view in dashboard inbox accounts customers followups chat-records tags tag-stats materials scope; do
  prof=$(mktemp -d)
  timeout 90 /usr/bin/google-chrome --headless=new --no-sandbox --disable-gpu --user-data-dir="$prof" --enable-logging=stderr --v=0 --virtual-time-budget=4000 --dump-dom "file://$HTML#$view" 2>"$OUT/$view.log" >"$OUT/$view.html"
  rm -rf "$prof"
  strip "$OUT/$view.html" "$OUT/$view.txt"
  errs=$(grep -ciE 'Uncaught|ReferenceError|TypeError|SyntaxError' "$OUT/$view.log")
  size=$(wc -c <"$OUT/$view.txt")
  terms=$(grep -c '邀请码' "$OUT/$view.txt")
  echo "view=$view js_errors=$errs rendered_bytes=$size invitation_code_lines=$terms"
  { [ "$errs" = 0 ] && [ "$size" -gt 15000 ] && [ "$terms" = 0 ]; } || FAIL=1
done
need() { grep -q "$2" "$OUT/$1.txt" && echo "ok   $1 contains: $2" || { echo "MISS $1 should contain: $2"; FAIL=1; }; }
need chat-records '聊天记录'
need chat-records '请选择平台'
need chat-records '社交账号'
need followups '跟进闭环中心'
whole=$(grep -c '邀请码' "$HTML")
echo "bundle_lines_with_term=$whole"
[ "$whole" = 0 ] || FAIL=1
echo "artifacts: $OUT"
[ "$FAIL" = 0 ] && echo "SMOKE PASS" || { echo "SMOKE FAIL"; exit 1; }
EOF
chmod +x /tmp/wa-scrm-plan-002/smoke.sh && ls -l /tmp/wa-scrm-plan-002/smoke.sh
```
