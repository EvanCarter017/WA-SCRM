## Why this matters

This product started as a clickable prototype that reviewers commented on. On 2026-11-21 the owner decided:

> "we should remove the elements from the prototype and proceed with the project as a formal, production-ready release."

Prototype elements fall into groups. Most of them stand in for something real that does not exist yet (simulated WhatsApp messages, fictional data, a role switch instead of a login); those go when their real counterpart is built, because removing a "demo" label from something that is still a demo would make the product claim what it cannot do. **This plan removes the one group that needs no replacement: the reviewer tools.**

1. The **review panel** `原型评审` and its two buttons: an icon in the top bar and a button floating over the bottom-right corner of every page.
2. The **requirements page** `功能范围` (address `#scope`), the last entry of the sidebar, with its "export requirements JSON" button.
3. The **notes tool**: Alt + click on any control opens a dialog to write a change request, which the preview server saves as a file (`POST /api/review-prompts`).
4. The **requirement records inside the app**: the app loads them from `requirements-data.js` and saves review states in the browser. After this plan the app does not load or save them. The file `requirements.json` is still generated by the build as a record; the validator reads it.

### Decisions already made (do not re-open; do not ask)

- Old links and old saved states must keep working: the address `#scope` opens the default page (the app already falls back for unknown page names), and a browser that saved review states or had the requirements page open loads normally.
- The link `恢复初始演示数据` (reset demo data) existed only at the bottom of the requirements page and disappears with it. Its action code stays in the app, unreachable, until the demo data itself is removed in a later plan. Do not add a new entry point for it.
- `requirements.json`, the requirement bookkeeping in `build-fidelity.cjs` and the validator's checks on it stay as they are.
- "Demo", "simulate" and "review" wording on other pages stays (it describes things that are still not real); only the tools listed above go.
- The build drops icons that are no longer used: the icon `Download` leaves `icons.js`. That is expected.
- Unused style rules for the removed elements stay in the style sheets (harmless; not worth the risk).
- `outputs/review-prompts/` (five old notes) stays as a historical record. The second command-line argument of `serve.cjs` (the notes folder) is no longer read; callers that still pass it keep working.
- The storage key and its version number, the version string `0.8-scrm-engagement` and `requirement.updatedOn` do not change.

### How the build works

`work/wa-replica/build-fidelity.cjs` reads a frozen baseline app (`work/wa-replica/fidelity-base/app.js`, **never edited**), applies string substitutions to it with a helper, and then puts the module files into the body of the same IIFE:

```js
let js = read(base, 'app.js');
function swap(from, to) {
  assert(js.includes(from), 'Missing prototype source anchor: ' + from.slice(0, 80));
  js = js.replace(from, () => to);
}
```

`swap` replaces the first occurrence of `from` and fails the build when it is missing. **Never change an existing `swap` call.** The last substitution of the script inserts the modules, and the line after it checks the syntax of the result:

```js
swap('  render();\n})();', [read(__dirname, 'fidelity-ui.js'), customerPages, operationsPages, openwaPages, dashboardPage, lifecyclePages, aiPages, subsiteSession].join('\n') + '\n  render();\n  window.initWAElementReview(toast);\n})();');
new vm.Script(js, {filename:'app.js'});
```

At that point `js` is the complete app. Step 4 inserts the removal between these two lines, so that it works on the final text and no existing substitution has to change.

Further down, the script builds the list of files it writes:

```js
const requirementJS = 'window.WA_REQUIREMENTS='+JSON.stringify(requirement)+';\n';
```

```js
const assets = {
  'index.html':index,'app.js':js,'app.css':read(base,'app.css')+'\n'+fidelityCSS,
  'tokens.css':tokenCSS,'components.css':read(base,'components.css'),
  'demo-data.js':read(base,'demo-data.js'),'icons.js':iconJS,
  'element-review.js':read(__dirname,'review-prompt-format.js')+'\n'+read(__dirname,'element-review.js'),
  'lucide-license.txt':read(base,'lucide-license.txt'),'requirements-data.js':requirementJS,
  'requirements.json':JSON.stringify(requirement,null,2)+'\n',
};
```

The build writes these files to `outputs/wa-replica-prototype/` (it never deletes a file there) and two identical standalone bundles, `outputs/whatsapp-scrm-lifecycle.html` and `outputs/whatsapp-replica-ui-fidelity.html`, in which every `<script src>` of the page shell is inlined. **Outputs are committed and must be regenerated by running the build, never edited by hand.**

Icons: the build takes icon definitions from the existing `outputs/wa-replica-prototype/icons.js` and keeps only the ones the app uses. Restore that file from git before every build (command below).

  '.html': 'text/html; charset=utf-8',
  '.css': 'text/css; charset=utf-8',

  '.json': 'application/json; charset=utf-8',

async function serveFile(req, res, pathname) {
  if (req.method !== 'GET' && req.method !== 'HEAD') {
    res.writeHead(405, { Allow: 'GET, HEAD' });
    return res.end('Method not allowed');
  }
  if (pathname === '/favicon.ico') {
    res.writeHead(204);
    return res.end();
  }
  const file = path.resolve(root, '.' + (pathname === '/' ? '/index.html' : pathname));
  if (!file.startsWith(root + path.sep)) {
    res.writeHead(403);
    return res.end();
  }
  const body = await fs.readFile(file);
  res.writeHead(200, {
    'Content-Type': mime[path.extname(file)] || 'text/plain; charset=utf-8',
    'Cache-Control': 'no-store',
  });
  res.end(req.method === 'HEAD' ? undefined : body);
}

const server = http.createServer(async (req, res) => {
  try {
    const pathname = decodeURIComponent(new URL(req.url, 'http://localhost').pathname);
    if (pathname.startsWith('/api/ai/')) await aiRelay.handle(req, res, pathname);
    else await serveFile(req, res, pathname);
  } catch {
    if (!res.headersSent) res.writeHead(404);
    res.end('Not found');
  }
});

server.listen(port, '127.0.0.1', () => {
  console.log('PREVIEW_URL=http://127.0.0.1:' + server.address().port);
});
process.on('SIGINT', () => server.close(() => process.exit(0)));
