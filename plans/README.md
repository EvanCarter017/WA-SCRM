## Owner request of 2026-11-17 (four improvements) and how it is split

The owner asked for: (1) hooks for future AI API integration, with no sales messaging; (2) a more detailed customer list with a D/C/B/A/S tier set by hand in the chat screen; (3) customer-list filtering by status (converted / abandoned order / organic lead), also set by hand in the chat screen; (4) the chat-history page reworked into a place where conversations from the WhatsApp chat are moved for performance review and auditing.

These are planned and executed one after another, each merged before the next is written, because they touch the same module:

- **003** — points 2 and 3 (customer tier and status).
- **004** — point 4 (chat history as a review and audit archive).
- **005** — point 1 (AI capability hooks). Written last so it can hook every place translation is produced. "With an eye toward future monetization" is implemented as metering only (a usage record per call, totals per capability, an on/off switch per capability); no price, plan or purchase wording appears anywhere, and the validator enforces that for the AI module. The plan was dry-run in a throwaway copy before dispatch, which corrected two of its own checks.

- **006** — owner feedback on 004, given the same day after seeing it: "The chat records do not need that rating system on the right, nor do they need to be categorized as 'qualified' or 'unqualified.'" The review form, the filter by result and the result labels that 004 added on the advisor's initiative are removed; the archive itself stays.
- **007** — a further owner request of the same day: "within the WhatsApp API chat interface, it should be possible to display tags directly on the customer card. It's fine if they aren't all fully visible, but at the very least, I should be able to get a general idea of the customer's status at a single glance." Read as: the cards in the conversation list show the customer's tags (first three, then +N). Tags only — nothing else is added to the card.
- **008** — owner feedback on 007, given the same day after seeing it: "Why are there still no tags appearing on the customer card? Instead of showing the funnel stage, it should display the tags that were created in the tag management section." Read as: the follow-up status chip on the card (awaiting reply / overdue / no plan / re-contact / ended) looked like a funnel stage and is removed, so the only status-like labels on a card are the customer's own tags. No tags were visible because none had been attached to a customer — a tag shows on a card only after it is set for that customer in the chat, and the prototype starts without tags. That was explained to the owner; nothing is seeded. The plan was dry-run before dispatch, which corrected one of its own checks.
- **009** — a further owner request of the same day, made on a screenshot with the follow-up status label and the next-follow-up label above an open chat marked: "Clicking here should navigate to the Follow Up page and track this event." "Track this event" was ambiguous (open the page on this customer's follow-up item, or record the click in the activity log), so the owner was asked and chose the first: the follow-up centre opens on the customer's row, highlighted — the to-do when there is one, otherwise the customer among the signals, or among the ended follow-ups. No log entry is written for the click. The plan was dry-run before dispatch, which corrected one of its own counts.

The owner does not review plans and has given a standing instruction to merge every change that passes review. Open design points are decided by the advisor and recorded in each plan under "Decisions already made".

## Owner request of 2026-11-18 (order tracking)

- **010** — made on a screenshot of the customer profile with its three tabs marked: "We should add a tracking feature here to monitor the status of a customer's orders—or perhaps adapt the existing 'Interactive Track' tool. For instance, I need to be able to see when a customer first reached out, the shipping status of each of their orders, and exactly when they placed an order with us." The owner was asked whether this should be a new tab or a change to the interaction timeline only, and chose the new tab. The owner also confirmed four points: orders are typed in by staff (nothing is connected to a shop or courier system); the shipping statuses are not shipped yet / shipped / delivered / problem (returned or lost); an order holds only its number, the time it was placed and its shipping status; adding an order does not change the customer status. Decided by the advisor and recorded in the plan: an order entered by mistake can be removed, with undo; every order change is written to the interaction timeline under its own filter; sample orders are added for the three demo customers whose story already mentions an order. The deals centre (quotes, repurchase reminders, lifetime value) stays deferred. The plan was dry-run before dispatch, which corrected one of its own counts and the order of two orders placed in the same minute.
